# Server test inventory

The pytest suite under `server/tests/`. Each file targets one layer and is named for the behavior it proves, so a failing test name reads as a sentence. The suite runs in CI after lint and needs no vendor accounts: the fixtures set `DEMO_MODE` before settings load and use a temporary SQLite file for anything that touches the cache.

## Fixtures

- [server/tests/conftest.py](../../../server/tests/conftest.py) sets `DEMO_MODE=1` (a default) and pins `SCHEDULE_TIMEZONE=UTC` (an assignment, so a zone exported in the shell loses too) before `config` is imported, so the settings load without credentials and the UTC instants and calendar days the suite asserts hold on a machine whose `server/.env` or shell names another zone, then provides `temp_db`: a fresh SQLite file under `tmp_path` with the repository's module-level connection reset, and demo mode switched off for the snapshot layer so the fetch callback a test passes is the one that actually runs. The connection is closed and reset after each test. Active.

## Cache and persistence

- [server/tests/test_snapshots.py](../../../server/tests/test_snapshots.py) proves the read-through cache in [snapshots](<../repositories/Reporting Repository - snapshots.md>): a miss fetches, stores and records sync state; a hit returns stored rows without calling fetch; refresh replaces the whole scope; scopes do not bleed into each other; an empty result is cached rather than refetched; and a fetch error keeps the old snapshot while recording the error. Active.

- [server/tests/test_schedule_repositories.py](../../../server/tests/test_schedule_repositories.py) round-trips the [presets](<../repositories/Reporting Repository - presets.md>) and [schedules](<../repositories/Reporting Repository - schedules.md>) repositories against a temporary database: a preset's `options` survive as a dict and stray keys such as `id` or `created_at` are ignored on insert and update; a schedule's recipient lists come back as lists and `enabled` as a bool; a run opens as `running` and closes with its status and saved report id; `due()` returns only enabled schedules with a non-null `next_run_at` at or before the given instant, soonest first, and compares correctly when the caller's instant carries microseconds and the stored value does not; `list_for_preset` returns only the schedules of one preset; deleting a schedule removes its runs; and a cache-version bump (`cache_meta.version` set back to 1, then the sqlite module's stale-cache discard) empties `device_rows` while leaving the preset, schedule and run rows in place. Active.

## Vendor client

- [server/tests/test_autotask_client.py](../../../server/tests/test_autotask_client.py) drives [the Autotask client](<../integrations/Reporting Integration - autotask.md>) with a stubbed session: `query_all` walks results with an anchored id cursor, `query_by_ids` chunks the `IN` filter, and picklists are fetched once per entity and field and skip inactive values. Active.

- [server/tests/test_renderer_client.py](../../../server/tests/test_renderer_client.py) drives [the renderer client](<../integrations/Reporting Integration - renderer.md>) with a patched `requests`: `render` posts the exact `reportType`, `data`, `options`, `filename` and `logoBase64` body to `{RENDERER_URL}/render` and returns the bytes with the response's content type, sends `{}` when options are `None`, defaults the content type when the header is missing, folds a non-200 status and the renderer's `{error}` text into a `RenderError`, and names the configured URL when the connection fails; `health` returns the parsed `/health` body and raises `RenderError` when the renderer is down or answers a 500. Active.

- [server/tests/test_delivery.py](../../../server/tests/test_delivery.py) proves [the delivery client](<../integrations/Reporting Integration - delivery.md>) posts the literal message the flow's trigger schema declares (`to`, `cc`, `subject`, `body` and base64 `attachments` with `name`, `contentType` and `contentBytes`) to `DELIVERY_WEBHOOK_URL` and accepts a 202; `message` copies the recipient lists and treats a missing `cc` as empty; an empty webhook URL raises a `DeliveryError` naming the setting before any request; a non-2xx answer raises a `DeliveryError` carrying the flow's `error.message` when the body has that shape and otherwise the body collapsed to one line and capped at 300 characters; a `ConnectionError`, `Timeout` or `ConnectTimeout` each raise a `DeliveryError` naming the failure kind and host while omitting the signed URL that the underlying `requests` error quotes; and `Attachment` is immutable. Active.

## Aggregation

- [server/tests/test_aggregates.py](../../../server/tests/test_aggregates.py) checks the arithmetic in the report services: ticket breakdowns sum to the ticket count, first-call resolution counts only phone tickets closed the same day by the taker, business-hours calculations skip nights and weekends, the SLA pivot grand total matches the ticket list, utilization totals reconcile, and period labels name the presets. Active.

## Core primitives

- [server/tests/test_core.py](../../../server/tests/test_core.py) covers the log buffer cursor surviving eviction and clear, cooperative cancellation raising at the next log line (see [jobs](<../core/Reporting Core - jobs.md>)), Office product name classification, primary-Office selection preferring a specific plan and then the newest edition, and storage sizes rounding up to the marketing size. Active.

- [server/tests/test_secrets.py](../../../server/tests/test_secrets.py) covers [secrets](<../core/Reporting Core - secrets.md>) against a temporary key path with `APP_SECRET_KEY` cleared: a value round-trips through `encrypt` and `decrypt` and is not stored in clear; a token read back as text decrypts the same as bytes, and a value that is not a token raises `SecretsError` saying so; a token still decrypts with `time.time` moved ten years ahead, proving tokens never expire; `secret.key` is generated once with owner-only permissions (the mode assertion is skipped on Windows) and reused after the cache is reset; `key_source()` answers `file`, keeps answering `file` after `APP_SECRET_KEY` is set because it reports the cached key, and answers `environment` only after `reset_cache()`; a key in `APP_SECRET_KEY` takes precedence and the file is never created; a file written by another worker between the existence check and the exclusive open is read instead of overwritten; an empty key file is read again once the other worker has written it (the retry sleep is patched to write the key), and one that stays empty raises `SecretsError` naming the path; decrypting after the key file is replaced raises `SecretsError` mentioning the current key; and a malformed key raises `SecretsError` naming `APP_SECRET_KEY` or the file path, whichever it came from. Active.

## Credentials

- [server/tests/test_credentials.py](../../../server/tests/test_credentials.py) covers the [credentials service](<../services/Reporting Service - credentials.md>) and [repository](<../repositories/Reporting Repository - credentials.md>) against a temporary database and key path, with the seven vendor variables deleted from the environment so a developer's `server/.env` cannot leak in: a trimmed environment value wins over a stored one and reports `source` as `environment`; a saved secret is not stored in clear, comes back from `current()`, shows `stored`, `configured` and its last four characters in `status()`, and never appears anywhere in the status JSON; an environment secret shows its last four too while a missing field has the documented empty entry; a blank value keeps the stored one; an unknown name is refused; a value for a field set by the environment is refused with the variable's name; the Autotask base URL must start with `https://` and loses its trailing slash; the Datto platform must be a lower-case hostname label and feeds `datto_api_base()` and `datto_token_url()`; a request with one bad field stores nothing; `invalidate()` and `save()` both run a registered listener; `current()` is cached until invalidated; `is_configured` needs every field of the vendor, from either source; `record_test` stamps only that vendor's rows and decodes to a bool; and the repository's `delete` removes a row. Active.

## Presets

- [server/tests/test_presets.py](../../../server/tests/test_presets.py) covers validation in [the presets service](<../services/Reporting Service - presets.md>): an unknown report type is refused, a devices preset needs an agency while an SLA preset has its agency dropped, options are filtered to the keys the renderer reads and `format` must be `docx` or `pdf`, device `columns` must be a list of names and an integer agency id is stored as text, a blank name is refused, `showLicenses` must be a bool, annual `companies` must be a list of strings and `rates` a dict of string keys to numbers or strings (a list, a `None` value, a list value and an integer key are each refused), `update` re-validates the merged row (so switching an SLA preset to `patch` without an agency fails) and raises `LookupError` for a missing id, deleting a preset is refused while a schedule references it and succeeds once that schedule is gone, and the set of report types matches the renderer's handler table. Active.

## Schedules

- [server/tests/test_periods.py](../../../server/tests/test_periods.py) covers [the periods service](<../services/Reporting Service - periods.md>): `previous_month` rolls January back to December of the year before; `previous_quarter` returns the inclusive ISO range of the calendar quarter before the run date, rolling Q1 back to the previous year's Q4; `fiscal_year_of_previous_month` returns the reporting year containing the previous month, so with a September start a run on 1 Oct 2026 reports the year in progress and a run on 1 Sep or 30 Sep 2026 reports the year that closed in August; and with `FISCAL_START_MONTH` overridden to 1 on the utilization module (where the arithmetic reads it) the result is the calendar year containing the previous month. Active.

- [server/tests/test_schedules.py](../../../server/tests/test_schedules.py) covers [the schedules service](<../services/Reporting Service - schedules.md>): `next_run_after` picks the coming occurrence in the schedule timezone and reflects a daylight-saving change between now and the candidate (from 9 Oct 2026 EDT, the 1st at 07:00 in `America/New_York` is `2026-11-01T12:00:00+00:00`, EST), runs today when the hour is still ahead and next month when it has passed or is exactly now, clamps the 31st to 30 Nov and to 29 Feb in a leap year, and writes `+00:00` rather than `Z`; `create` normalizes addresses to lower case, drops blank entries, treats a missing `cc` list as empty, refuses an empty `to` list, a malformed address, a day of 0, an hour of 24, a blank subject, a missing preset, a non-integer or null day or hour and a fractional day or hour (`7.5` is refused, `7.0` accepted) with a message naming the field, accepts a bare string as one recipient and rejects a bare non-address string naming it, and reports a bad `SCHEDULE_TIMEZONE` as a `ValueError` naming the setting; `update` moves `next_run_at` when the day changes, clears it when the schedule is disabled, recomputes it when re-enabled, re-validates recipients and raises `LookupError` for a missing id; `advance` moves `next_run_at` past a run that just happened; `record_result` writes `last_run_at`, `last_status` and `last_error` and clears the error on a later success; and `list_schedules` carries each schedule's preset row while `delete` removes the schedule. Active.

- [server/tests/test_scheduled_runs.py](../../../server/tests/test_scheduled_runs.py) drives [the scheduled runs service](<../services/Reporting Service - scheduled_runs.md>) with the tenant, the report services, the renderer and the delivery flow patched and the clock fixed at 1 Nov 2026: a device run gathers one sheet per member with its `companyName`, renders `devices` with the preset's `columns`, saves under `<agency> Computer Inventory 11-1-26.xlsx`, delivers the rendered bytes and content type as the attachment with the filled subject, and closes the run and the schedule as `ok`; a `RenderError` closes the run as `error` with its text, leaves `saved_report_id` empty and never calls delivery; a `DeliveryError` after the save keeps `saved_report_id` on the error run; an SLA run asks for October 2026, fills `{period}` as `October 2026` and names the file `SLA Performance By Ticket October2026.xlsx`; with the real `_today` restored, `_now` frozen at 02:30 UTC on 1 Nov 2026 and the zone set to `America/New_York`, `_today()` is 31 Oct 2026 and the SLA run asks for September 2026 with the subject `SLA performance September 2026`, while an unknown zone makes `_today()` raise a `ValueError` naming `SCHEDULE_TIMEZONE`; an unknown `{nope}` placeholder stays literal while `{date}` fills as `November 1, 2026`; `_fill` leaves `Totals {`, `a } b`, `{} x`, `{agency:>6}` and `{agency` exactly as typed and replaces only known placeholders; an agency key that no longer resolves fails the run naming the key before anything is rendered or sent; `trigger="schedule"` calls `schedules.advance` and `manual` does not, each leaving a run row; with `advance` unpatched a scheduled run moves `next_run_at` from 1 Nov to 1 Dec 2026; an `advance` that raises closes the run as `error` before anything is rendered or sent; the body is HTML-escaped with apostrophes kept and newlines as `<br>`; one run goes through the real `delivery.send` with only `requests.post` faked and the posted JSON carries `to`, the filled `subject`, the `<br>` body and one attachment whose `contentBytes` decode to the rendered bytes; - [server/tests/test_schedule_runner.py](../../../server/tests/test_schedule_runner.py) covers [the schedule runner service](<../services/Reporting Service - schedule_runner.md>). A `live` fixture patches `schedules.get` to answer an enabled row for any id and `due` to answer nothing, so no runner test reaches the real database file; each test then patches `due` and `run_schedule` for its case: a tick runs each due schedule once, in order, with trigger `schedule` on one thread; `run_now` answers `True` and names the schedule in `status()` while the run is in flight, answers `False` for a second request, and reports idle once the run ends; a tick during an in-flight run starts nothing and the due schedule is picked up by the next tick after it finishes; a `run_schedule` that raises (on a temporary database) is logged as `[ERROR] Schedule <id>: <reason>` on the stream and the remaining ids still run; a schedule that `get` no longer finds, or finds disabled, is skipped with an `[INFO]` line while the rest of the batch runs, and a manual run-now still runs the disabled one but not the missing one; and `sweep_interrupted` (against a temporary database) closes only the runs still in `running` as `error` with `Interrupted by a restart`, stamps `finished_at`, leaves finished runs untouched and reports the count. - [server/tests/test_schedule_routes.py](../../../server/tests/test_schedule_routes.py) drives [the presets router](<../routers/Reporting Router - presets.md>) and [the schedules router](<../routers/Reporting Router - schedules.md>) through `TestClient` against a temporary database: an unknown report type is a 400 naming it; a preset is created with 201, listed, renamed with a partial PUT, and a PUT for a missing id is a 404; a schedule is created with 201 joined with its preset and a `next_run_at`, listed, disabled by a partial PUT that clears `next_run_at`, refused with a 400 naming `hour` when the hour is 24, and a PUT for a missing id is a 404; deleting a preset that is still scheduled is a 409 and succeeds with `{deleted: true}` once the schedule is deleted, after which deleting either id again is a 404; run-now answers 202 `{started: true}` and passes the id to the runner, 409 naming the schedule the runner reports as running when it refuses, and 404 for an unknown schedule; `/status` passes the runner's status through; `/runs` lists the newest runs across schedules with a `limit`, while `/{id}/runs` lists one schedule's; `/test-delivery` answers 502 naming `DELIVERY_WEBHOOK_URL` when the webhook is unset, `{sent: true}` after calling `delivery.send` with the given recipients, an empty `cc`, the subject `Reporting: delivery test`, a one-line body and no attachments, and 422 without a `to` list; and `/renderer-health` passes the renderer's health JSON through or answers 502 with the `RenderError` text.
