# Server test inventory

The pytest suite under `server/tests/`. Each file targets one layer and is named for the behavior it proves, so a failing test name reads as a sentence. The suite runs in CI after lint and needs no vendor accounts: the fixtures set `DEMO_MODE` before settings load and use a temporary SQLite file for anything that touches the cache.

## Fixtures

- [server/tests/conftest.py](../../../server/tests/conftest.py) sets `DEMO_MODE=1` (a default) and pins `SCHEDULE_TIMEZONE=UTC` (an assignment, so a zone exported in the shell loses too) before `config` is imported, so the settings load without credentials and the UTC instants and calendar days the suite asserts hold on a machine whose `server/.env` or shell names another zone, then provides `temp_db`: a fresh SQLite file under `tmp_path` with the repository's module-level connection reset, and demo mode switched off for the snapshot layer so the fetch callback a test passes is the one that actually runs. The connection is closed and reset after each test. It also provides `store` (on top of `temp_db`: a key file under `tmp_path`, `APP_SECRET_KEY` blanked, the secrets cache reset, the seven vendor variables deleted so a developer's `server/.env` cannot leak in, and the credentials listener list copied so the vendor clients' import-time registrations survive while a test's own are discarded) and `configured` (both vendors saved from `SAMPLE_AUTOTASK` and `SAMPLE_DATTO`, returning the values). Active.

## Cache and persistence

- [server/tests/test_snapshots.py](../../../server/tests/test_snapshots.py) proves the read-through cache in [snapshots](<../repositories/Reporting Repository - snapshots.md>): a miss fetches, stores and records sync state; a hit returns stored rows without calling fetch; refresh replaces the whole scope; scopes do not bleed into each other; an empty result is cached rather than refetched; and a fetch error keeps the old snapshot while recording the error. Active.

- [server/tests/test_schedule_repositories.py](../../../server/tests/test_schedule_repositories.py) round-trips the [presets](<../repositories/Reporting Repository - presets.md>) and [schedules](<../repositories/Reporting Repository - schedules.md>) repositories against a temporary database: a preset's `options` survive as a dict and stray keys such as `id` or `created_at` are ignored on insert and update; a schedule's recipient lists come back as lists and `enabled` as a bool; a run opens as `running` and closes with its status and saved report id; `due()` returns only enabled schedules with a non-null `next_run_at` at or before the given instant, soonest first, and compares correctly when the caller's instant carries microseconds and the stored value does not; `list_for_preset` returns only the schedules of one preset; deleting a schedule removes its runs; and a cache-version bump (`cache_meta.version` set back to 1, then the sqlite module's stale-cache discard) empties `device_rows` while leaving the preset, schedule and run rows in place. Active.

## Vendor client

- [server/tests/test_autotask_client.py](../../../server/tests/test_autotask_client.py) drives [the Autotask client](<../integrations/Reporting Integration - autotask.md>) with a stubbed session and a fixed `Connection`: `query_all` walks results with an anchored id cursor, `query_by_ids` chunks the `IN` filter, and picklists are fetched once per entity and field and skip inactive values. With the `configured` fixture and the default connection, a request goes to the stored base URL with the stored username, secret and integration code as headers, a secret saved afterwards is on the very next request, a save clears the process-wide client's picklist cache so the next lookup downloads again from the new base URL, and with nothing configured the client raises `CredentialsMissing` naming Settings before any request. The probe posts exactly `{filter: [{op: eq, field: id, value: 0}], maxRecords: 1, includeFields: [id]}` to `<base>/Companies/query` with the connection's headers and answers `CONNECTED`, a session whose response raises an `HTTPError` makes it answer `HTTP 401` with the body collapsed and the caller's redaction applied, and `connection_from` builds the three headers and base URL from a plain values dict. Active.
- [server/tests/test_datto_client.py](../../../server/tests/test_datto_client.py) drives [the Datto client](<../integrations/Reporting Integration - datto.md>) through `datto()` with a stand-in for `requests` that hands out numbered tokens: the first GET posts the password grant with the stored key and secret to the platform's token URL and the second reuses the token; a `save()` of a new secret and platform drops the token, so the next GET fetches one with the new secret from the new platform's URL and calls the new API host; and with nothing configured the GET raises `CredentialsMissing` naming Settings with no request made. A throwaway provider built from `token_request_from(SAMPLE_DATTO)` makes `probe` post one password grant to that platform's token URL, with no GET, and answer `CONNECTED`; a `requests` stand-in whose `raise_for_status` raises makes it answer `HTTP 401: invalid_client`. Active.
- [server/tests/test_http_errors.py](../../../server/tests/test_http_errors.py) covers [the http_errors integration](<../integrations/Reporting Integration - http_errors.md>): `trimmed` collapses runs of whitespace and cuts at 300 characters; an `HTTPError` carrying a response is described as `HTTP <status>: <trimmed body>` with the URL from the exception's own text absent; a `ConnectionError` is described by its class name alone; a call that returns is `CONNECTED`; a `KeyError` from a malformed body and a `requests.JSONDecodeError` are both the not-JSON result; a plain `ValueError` is `Request not sent: ValueError`; and a redaction passed to `probe` is applied before the cut, so a value placed across the 300th character leaves no fragment. Active.

- [server/tests/test_renderer_client.py](../../../server/tests/test_renderer_client.py) drives [the renderer client](<../integrations/Reporting Integration - renderer.md>) with a patched `requests`: `render` posts the exact `reportType`, `data`, `options`, `filename` and `logoBase64` body to `{RENDERER_URL}/render` and returns the bytes with the response's content type, sends `{}` when options are `None`, defaults the content type when the header is missing, folds a non-200 status and the renderer's `{error}` text into a `RenderError`, and names the configured URL when the connection fails; `health` returns the parsed `/health` body, raises `RenderError` when the renderer is down or answers a 500, and raises `RenderError` (not `ValueError`) for a 200 whose body is not JSON. Active.

- [server/tests/test_delivery.py](../../../server/tests/test_delivery.py) proves [the delivery client](<../integrations/Reporting Integration - delivery.md>) posts the literal message the flow's trigger schema declares (`to`, `cc`, `subject`, `body` and base64 `attachments` with `name`, `contentType` and `contentBytes`) to `DELIVERY_WEBHOOK_URL` and accepts a 202; `message` copies the recipient lists and treats a missing `cc` as empty; an empty webhook URL raises a `DeliveryError` naming the setting before any request; a non-2xx answer raises a `DeliveryError` carrying the flow's `error.message` when the body has that shape and otherwise the body collapsed to one line and capped at 300 characters; a `ConnectionError`, `Timeout` or `ConnectTimeout` each raise a `DeliveryError` naming the failure kind and host while omitting the signed URL that the underlying `requests` error quotes; and `Attachment` is immutable. Active.
